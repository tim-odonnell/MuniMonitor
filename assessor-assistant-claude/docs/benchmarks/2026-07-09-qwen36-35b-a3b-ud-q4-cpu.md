## 3. Methodology (the how-to-test)

1. **Raw throughput** (clean, uncontended, before any server runs):
   `llama-bench -m <gguf> -p 2048 -n 128 -t <threads>` → records pp2048 (prompt
   processing tok/s) and tg128 (generation tok/s).
2. **Serve** via the assessor project's launcher (auto-updates its config):
   `cd assessor-assistant-claude && ./serve.sh <model-filter> --port 18098`
3. **Point the other two projects** at the same server (edit their `config.json`
   `llm.base_url`/`llm.model` — one server serves all three).
4. **Functional gauntlet** (identical to every other rung; all cases carry
   deliberate traps):
   - Assessor: `python3 src/backtest.py` — 3 demo PTAs incl. the use-change trap
     (DEMO-PTA-003). Gates: 3/3 agreement, **0 missed uncaps**, 0 ungrounded cites.
   - Clerk: `python3 src/foia_backtest.py` — 3 demo FOIA requests incl. the
     personnel trap and the attorney-client sweep. Gates: **0 missed review
     flags**, 0 ungrounded cites.
   - Building: 3 `src/ask.py` questions — (a) inspector registration (expected:
     PA 407-grounded, cited), (b) "is the 2021 residential code in effect?"
     (expected: injunction-aware answer), (c) smoke-alarm locations (expected:
     grounded R314 answer from the Michigan amendment rules). Answers checked
     with `citations.validate_citations` against the retrieved chunks + human
     read for grounding.
5. **Speed capture:** per-request `prompt eval` / `eval` tok/s lines from the
   server log; wall-clock per case from the harness output.
6. **Restore** configs to their prior endpoints; commit this document + the
   descent-protocol ledger row.

Judgment criteria are the descent protocol's (docs/model-descent-protocol.md §
per-rung procedure); the zero-tolerance classes veto regardless of other scores.

## 4. Results

*(appended as measured)*

### 4.1 Raw throughput (llama-bench, uncontended, -t 24)

| test | result |
|---|---|
| pp2048 (prompt processing) | **127.8 ± 11.2 tok/s** |
| tg128 (generation) | **11.0 ± 0.7 tok/s** |

Server-measured under load: PP 149-161 tok/s (2.3-2.8K prompts), TG steady
12.0-12.1 tok/s. Model load: ~6 minutes (22.9GB from disk, first run).

### 4.2 Functional results (all zero-tolerance gates PASSED)

| Department | Cases | Result | Wall/case | Citations |
|---|---|---|---|---|
| Assessor (PTA triage) | 3 demos incl. use-change trap | **3/3 agree, 0 missed uncaps** | 267-384s | 12 checked, **0 ungrounded** — incl. full chunk-label format `[mcl-211-27a.md#6]` |
| Clerk (FOIA triage) | 3 demos incl. personnel + attorney-client traps | **3/3 agree, 0 missed flags** — and the routine-minutes case correctly NOT flagged (the vLLM/REAP run had false-flagged it) | 262-272s | 13 checked, **1 flagged** — verified benign: "(MCL 15.231 et seq.)" in the acknowledgment letter, the standard citation for the act as a whole, factually correct but cited from memory rather than provided text. | Building (Q&A) | 3 questions | **All grounded**: PA 407 registration cited; **code-currency answer correctly injunction-aware** ("2015-edition rules remain in effect… re-check before relying"); smoke-alarm answer grounded in the Michigan amendment rules | 129-253s | 10 checked, **0 ungrounded** |

Citation precision notably HIGHER than the vLLM/REAP run: subsection-level
statute cites (15.243(1)(s)(ix), (1)(s)(iii), (1)(w)) and proper chunk-label
format throughout.

### 4.3 Latency anatomy (matters for the 32GB target box)

Per triage case ≈ 90s prompt processing (~13-14K tokens @ ~150 tok/s) +
3-5 min generation — **generation of the thinking trace (~2,000-2,900 tokens
@ 12 tok/s) dominates, not prompt processing.** Levers if latency matters:
shorter thinking (chat_template_kwargs), or GPU offload. On the DDR5-5600
target box, expect ~1.3-1.5× these speeds (higher memory bandwidth).

### 4.4 Verdict

**PASS — strongest rung result to date.** All six trap cases across three
departments, zero zero-tolerance violations, best citation fidelity measured
so far, on the portable CPU-only engine via serve.sh (the exact target-machine
path). Generation 11-12 tok/s ≈ 4× the stated 3 tok/s floor. RAM note: 21.3GiB
model + KV fits the 32GB target with --ctx 16384 and --parallel 1, nothing
else heavy running.
